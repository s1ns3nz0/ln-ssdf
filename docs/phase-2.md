# Phase 2 — regtest lnd and dynamic PostgreSQL credentials

`charts/bitcoind` supplies the isolated regtest chain. `charts/lnd` runs a primary
PostgreSQL-backed lnd and a bbolt peer. Wallet seed and password are generated by
the official `lndinit` release, stored only in Vault KV v2, and synced by VSO to
the two wallet Secrets. The chart verifies the release archive SHA-256 before
executing it from an `emptyDir`.

Run `scripts/phase2-bootstrap.sh --context kind-ln-ssdf-phase0 --state-dir
ABSOLUTE_PATH` after Phase 1 and bitcoind are installed. The primary consumes only
the `username` and `password` keys from `lnd-db-credential`; it never receives the
Postgres bootstrap account. Each Vault lease logs in then assumes `lnd_runtime`,
so schema ownership survives a lease rotation.

The completed local Phase 2 acceptance drill opened a 1,000,000 sat channel and
made payments in both directions. It then revoked all old `database/creds/lnd`
leases, confirmed that only the current dynamic login remained usable, restarted
primary lnd, and made both payments again. This credential-rotation check is a
separate acceptance step from the destructive rebuild script below.

For the long-running VSO lifecycle, set `STATE_DIR` to the absolute Phase 1
recovery directory outside Git, then run this after Phase 2:

```bash
scripts/phase2-db-rotation-drill.sh --context kind-ln-ssdf-phase0 \
  --state-dir "$STATE_DIR"
```

The drill temporarily gives the Vault `lnd` role a 90-second default and 180-second
maximum TTL, proves VSO extends PostgreSQL `rolvaliduntil` on renewal, then
proves a new Secret restarts LND with the new role. It restores the normal
one-hour/two-hour role TTL, forces a normal lease, and settles a payment after
the final restart. An exit trap restores the role TTL if the drill fails; check
the active lease and Pod before relying on the workload after a failed drill.
The Secret-backed DB environment variables cannot change inside an existing
Pod. The chart's `lndinit` init container also downloads its pinned release
archive on every Pod restart, so network availability affects rotation recovery.

`scripts/phase2-rebuild-drill.sh` deletes only the explicit local kind cluster,
restores the Vault Raft state held in the host recovery directory (including KV
wallet data, policies, and Kubernetes auth configuration), and creates a fresh
regtest chain, lnd state, channel, and two payments. It proves
install/recreation, not Lightning channel recovery: the old regtest chain and
peer PVC are deliberately destroyed, so old channels cannot exist after the
drill. It does not repeat the credential-rotation acceptance step.
